# ラウンド探索計画の採点と改訂記録

更新日: 2026-09-12。対象: [ラウンド探索の実装計画](round-research-plan.md) 第2版。

## 評価の範囲

これは実装計画のレビュー担当AIによる採点であり、独立した第三者評価でも、実装済みソフトウェアや調査結果の品質点でもない。ユーザーの「95点になるまで改善する」という依頼に対し、以下の配点を初回から固定し、減点を解消する改訂を行った。点数自体を改善の証拠にはせず、指摘と対応箇所を根拠とする。

| 指摘 | 改善内容 | 計画の対応箇所 |

| 回答項目を資料に合わせて狭める余地がある | 原文との対応、required/optional、変更禁止、十分性の整合検査を追加 | 11.1 |
| 選出全件の完了とfetch成功、失敗、停止の関係が不明 | Round遷移、選出集合version、read終端、空選出を定義 | 11.2 |
| 予算切れ後にLLM評価へ進む記述が実行不能になり得る | 最終工程の予約、中間評価枠、時間境界、LLMなしの部分出力を規定 | 11.3 |
| 既存reserveと新しい将来予約がusageへ二重加算され得る | v2予約台帳と精算、v1分離を明記 | 11.3 |
| 外部推論停止を確認できないままlease期限で二重実行し得る | persistent slot、blocked、外部停止確認、保証範囲を具体化 | 11.4 |

| 候補追加中の古い評価で次ラウンドを確定し得る | revision比較、限定再判断、持越しと反映予定の返却を定義 | 11.5 |
| 原依頼の途中変更まで含み、実装範囲が広い | 原依頼変更は別Jobへ限定 | 11.5 |

第1改訂は91点。方針と状態契約は明確になったが、最終レビュー失敗時と比較評価の合格条件が不足していた。

第2改訂は95点。要件から実行契約、復旧、最終出力、検証まで追跡でき、重大な未解決矛盾は本レビューでは見つからなかった。

## 残る5点と実装前後の確認

- 判断契約 −1: 期待価値の閾値5/6が実際の読者評価に合うかは未校正。固定ケースと人間の評価で検証する。
- 実行・復旧 −1: 採用するLocalLLMの停止・完了確認能力は未検証。確認不能時はblockedを維持する仕様とし、復旧時間は保証しない。
- 予算・終了 −1: 小さいモデルでの圧縮量、応答長、所要時間の見積りは未測定。初期上限による保守的運用から計測する。
- 検証可能性 −1: 品質比較の担当者とLocalLLM環境は未確保。実装の固定テスト合格と品質改善の実証を分ける。
- 導入可能性 −1: 旧Job・各CLI・既存予算台帳を新workerへ通す互換コストは未実装のため未実証。M2の移行テストで確認する。

これらを曖昧なまま実装者へ委ねるのではなく、失敗時の挙動と検証工程は計画に含めた。実測なしに100点や品質改善済みとは評価しない。
