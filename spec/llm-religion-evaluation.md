# 「LLMと宗教」実調査・改善記録

2026年9月12日。Codex SDK 0.135.0、gpt-5.6-luna、reasoning lowで実行した。検索はCodex Web、取得・抽出はllm-fetch、プロンプトはs11tnext。DataForSEOやLARMの実接続成功を意味するものではない。

## 成果物

採用版はJob `a03b6f47-2a86-409e-a6f0-870a6a66ad8e` のArtifact v3。`data/artifacts/<jobId>/3/` に `report.md`、`report.html`、`evidence.json` がある。UIは最新の版を表示し、Markdownをダウンロードできる。

8資料・6ドメイン・26件の根拠参照、5章・14段落のレポートを作成した。法判断の生成、経典の引用、宗教集団の表象、対話相手に与える役割を分けて検討する構成。研究結果、開発側の説明、倫理的提言、執筆者の考察を区別した。

今回の結果は、取得できた一次資料に基づく探索的レビューとして合格と判断した。文献の網羅性、論文本文の精査、因果効果の再現検証まで達したという評価ではない。

## 評価基準と結果

各5点。4を十分な水準、5を優れた水準とした。構造検証に加え、全5項目が4以上かつ重大な指摘0件を合格条件とした。評価モデルの `verdict` がpassでも、重大な指摘が残れば不合格とする。

評価はluna / lowの別呼び出しで行い、担当エージェントも本文と引用を照合した。同じモデル系統による評価であり、独立した人間の査読ではない。v3は担当エージェントが指摘と原文を踏まえて編集した。v2の判定不整合を受け、合格条件のプログラム検証と、重大な誤りと今後の追加研究を区別する評価指示も追加したため、点数だけを固定評価条件での性能向上と解釈しない。

詳細は `data/reviews/<jobId>/v1.json`、`v2.json`、`v3.json`。編集内容も同じディレクトリに保存した。

## 発見した不具合と修正

1. 初回の比較Job `81711275-2658-4b84-bed6-75612068d949` は、17 URL、5抽出処理を実行したが、概念数の上限超過等で全応答がスキーマ不正となり、採用主張0件で終了した。プロンプトだけのJSON指定から、必須プロパティを持つ構造化出力へ変更した。
2. モデルが原文の改行を空白に直すため引用を拒否していた。一意な空白正規化一致だけを原文へ写像するよう修正し、保存済み応答から11件を回復した。保存する引用、hash、UTF-16 offsetは原文との完全一致を保つ。曖昧な一致や語句の差は受け入れない。
3. 統合時に参照UUIDの誤記と重複した参照一覧の不整合が発生した。生成スキーマを採用済みIDのenumに限定し、一覧は段落の参照からアプリが導出する方式にした。不正な参照の採用や推測修正はしない。
4. 英語の事実列挙から、日本語の章・段落、根拠参照、考察、調査の限界、未解決の問いを持つレポートへ拡張した。改稿前の版も保持する。
5. 長い段落が文字数制限のため丸ごと除外されていた。原文位置を保持して分割し、日英のクエリと資料タイトルも本文選択に用いた。
6. 検索が論文の要旨に偏ったため、担当エージェントが不足する探索クエリを追加し、AI JesusとRome Callの公式ページを補足した。介入は `query.focus_added` と `job.quality_revision_started` に記録した。完全無人の探索として扱わない。
7. 実資料で旧文字コードへの未対応を確認し、ISO-8859-1 / Windows-1252のHTMLを安全なHTTP取得後に変換する処理を追加した。guardは変更せず、遮断された資料は採用しなかった。
8. SDKによる呼び出しがユーザーのMCP設定を継承し、1回の抽出でContextStillのread-only toolを使用した。各MCP serverの明示的な無効化と、想定外のtool使用の拒否を追加した。修正後の疎通と統合・評価では不要なtool使用がないことをauditで確認した。

## 利用量と再現

本Jobの検索・抽出・統合の実usage合計は740,256 tokens。v1〜v3の評価とv2への改稿は別実行で159,449 tokens。これらの合計は899,705 tokens。比較用初回Jobや疎通確認はこの合計に含めない。金額0はDataForSEO課金を発生させていないという記録であり、Codexの購読利用や推論が無料という意味ではない。

再実行は `bun run research 'LLMと宗教'`、評価は `bun run research:review <jobId>`、改稿は `bun run research:revise <jobId>`。結果は検索時点やモデルの応答によって変わる。取得・推論を再実行せず確認する場合は保存済みsnapshot、invocation、Artifact、評価JSONを使用する。
