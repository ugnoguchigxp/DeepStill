## 修正した問題

| 重要度 | 問題 | 対応・検証 |
| --- | --- | --- |
| 高 | 古い同梱CLIへ暗黙にフォールバックする | グローバルCLIまたはCODEX_PATHを明示的に解決。見つからない場合は開始不可。CLIのバージョンも確認 |
| 高 | Workerが停止・旧版でも準備完了となる | Workerのハートビートとコード・依存・設定ファイルの版を検査。APIで開始・再開を拒否し、画面に原因を表示 |
| 高 | JSON出力を文章で依頼するだけ | 検索語・検索結果にStructured Outputsを適用。ローカルのZod検証も維持 |
| 高 | Structured Outputsに非対応のuri形式を渡す | 送信スキーマからuri形式だけを除外。URLの検証は受信後も実施 |
| 高 | 生成前に探索で予算を使い切る | 収集済み根拠から生成用トークンとリクエストを確保。予算が近づいたら生成へ移行 |
| 高 | Providerの初期化例外でタスクが実行中のまま残る | 初期化もWorkerのエラー処理に含め、終了状態を永続化 |
| 高 | 中止・再開がWorkerや予算の状態に依存し過ぎる | 未実行タスクはWorkerなしでも中止可能。検索件数の上限だけで本文抽出・生成の再開を拒否しない |
| 高 | 不正な生成結果を再開後も再利用する | 不正な応答は明示的な再開で再試行。正常な生成結果は中止後も再利用する。過去の記録と予約使用量は保持 |
| 高 | 反証がレポートから除外される | 原文一致・参照先・信頼度を満たす対立する知見も生成へ渡す。既存知見との関係を明示 |
| 高 | 失敗URLの反復取得と出典の偏り | 取得失敗を保存し、検索へ既存資料・失敗履歴を渡す。繰り返し取得を抑制 |
| 中 | 別テーマにも宗教専用の指示が残る | 抽出・評価の指示を汎用化。テーマの基礎・仕組みを検索し、無関係なリリース情報を除外 |
| 高 | PDFを一律に取得対象外とする | unpdfで本文抽出。元PDFのハッシュ・ページ数を保持し、抽出後もllm-fetchのガードを適用 |
| 中 | 日本語旧文字コードと出力HTMLの文字コード | Shift_JISなどの明示的な文字コードを変換。HTMLにUTF-8とDOCTYPEを指定 |
| 中 | 開発サーバー停止でラッパーの子が残る | 実プロセスを直接管理。Worker停止時は進行中の処理へAbortSignalを渡す。Viteはポート競合時に別ポートへ逃げない |
| 中 | Honoの公開済み脆弱性3件 | 4.13.5へ更新。依存の整合性と回帰テストを確認 |

Structured Outputsの使用は[OpenAIの公式仕様](https://developers.openai.com/api/docs/guides/structured-outputs)に合わせた。uri形式の拒否は実リクエストでも再現し、修正後の実検索で解消を確認した。

## 対応範囲

PDFはテキストを持つ文書が対象で、OCRは行わない。取得は10MB、PDFは100ページ・抽出本文20万文字を上限とする。llm-fetchのガードで拒否される資料は自動で採用せず、取得失敗として扱う。外部サイトの拒否や、収集した資料にない論点まで解消したとはみなさない。

Codexの使用量は応答後に確定するため、処理中は予約値を含む。品質評価・改稿の補助コマンドは調査本体と別に使用量を記録する。今回の検証はすべての潜在的な不具合が存在しないことの証明ではなく、確認した問題の修正と、再現条件を持つ回帰検証である。
