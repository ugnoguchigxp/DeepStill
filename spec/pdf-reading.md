# PDFの本文抽出・ページ引用・品質評価

## 実装範囲

2026-09-13の依頼の1・2・4に対応する。ページ位置と未読範囲を保存し、水平な一段組み・明確な二段組みの読み順を改善する。評価は外部APIやOCRモデルなしで再現する。

既存unpdfに含まれるPDF.jsを利用する。追加依存、OCR、画像の意味解析、汎用CV、SAAAへの変更は含まない。将来の専用プロジェクトは同じページ単位の結果を返すAdapterとして接続できる。Docling等のモデルを用いた解析の導入・実機比較は今回実施していない。

## 保存と引用

Snapshot.pdfの既存rawHash・pagesに、任意のpageMap・omittedPages・coverage・warningsを追加した。DBは既存JSON保存を使い、マイグレーションや認証・新規APIは不要。旧Snapshotはそのまま読めるが、ページ番号を推測して補わない。

pageMapは、PDFファイル先頭を1としたページ番号、保存本文に対するUTF-16のstart/end、抽出方法embedded-text、layout、status、警告を持つ。印刷されたページ番号とは区別する。本文のないページは空の区間を持ち、引用対象にならない。

| status | 意味 |
| --- | --- |
| extracted | 埋め込み文字を抽出し、実装済みの検査で問題を検出しなかった。意味理解の完全性を保証しない |
| partial | 本文はあるが、画像・図形・注釈・配置・文字化け・抽出上限などの未確認要素がある |
| unread | 当該ページの利用可能な本文がなく、視覚内容や解析失敗などがある |
| blank | 文字、検出対象の描画命令、未読注釈を検出しなかった。画素比較による白紙認定ではない |

本文ガード通過後の文字列が抽出結果の同一prefixであることを検査してからページ位置を付ける。短縮されたページはpartial/unreadとし、未知の変換があればページ位置を提供せずPDF_POSITION_UNAVAILABLEを記録する。引用は従来どおり保存本文との一致を検査する。

引用画面、HTMLの根拠一覧、Markdownの出典にPDFページを表示する。画面とHTMLの原典リンクには最初の該当ページのフラグメントを付ける。ページ番号はEvidenceに重複保存せず、Snapshotの区間から導出する。source_index、source_rangeと調査のLLM入力にも読み取り状態を渡す。

## 抽出と上限

取得の10MB制限は維持する。Content-Typeに加え、先頭1024バイト内の空白に続くPDFシグネチャを検査する。application/octet-streamはPDFと確認できた場合だけ解析し、それ以外のバイナリは拒否する。URLの拡張子だけでPDFとは判定しない。

100ページ、保存本文10万文字までを抽出する。後段の既存10万文字制限に合わせ、以前の「抽出20万文字・後段10万文字」という二重の上限をそろえた。上限を超える文書を全体エラーにせず、取得済み本文と、残りのページ範囲・理由を保存する。ページ途中で切れた場合も記録し、サロゲートペアを途中で切らない。

画像・図形の描画命令、リンク以外の注釈、40文字未満の非空本文、置換文字、未対応の方向を検査する。画像ページと本文ページが混在していても、画像ページを読了とは扱わない。全文が抽出不能なら従来どおりPDF_NO_EXTRACTABLE_TEXTで失敗し、エラーにはページ別の診断結果を添える。OCRへ自動遷移しない。

文書ロード前からキャンセルを接続し、終了時にPDF資源を破棄する。ページの解析に失敗した場合はそのページを未読にし、後続のページを継続する。壊れた文書や暗号化等で文書自体を開けない場合は失敗する。

## 読み順と限界

文字の座標・大きさから行を組み立てる。中央付近の空間の両側に3行以上の一定長の本文があり、縦方向の範囲が重なる場合を二段組み候補とする。全幅の見出しを境界に、各領域を左段から右段へ読む。上部・下部の余白文字と下部の小さな文字は本文の段間に挟まず保持する。

複数セルらしい配置は行順を保持してTABLE_LAYOUT_UNVERIFIEDとする。縦書き、回転、右から左への本文は取得順を保持して未確認とする。ハイフン除去や数式の書き換えは行わない。

これは配置の規則による改善であり、任意の論文の読順を保証するものではない。複雑な段組み、2列の長文表と本文の区別、ページをまたぐ脚注、数式、文字として描かれたグラフなどには限界がある。視覚情報の未読判定も描画命令に基づく保守的な検出で、OCRや画像比較ではない。

## 評価方法

tests/helpers/pdf-fixture.tsが座標・文字・画像・図形を指定したPDFを生成する。日本語はToUnicodeを持つフォント参照を使用する。外部論文の再配布、ネットワーク、OCR、モデル資格情報は不要。

| ケース | 変更前 | 変更後の検証 |
| --- | --- | --- |
| 左右の段が交互に格納された論文 | 取得順に連結 | 左段の末尾が右段の先頭より前になる |
| 全幅見出しと脚注 | 段や余白の区別なし | 領域ごとに読順を復元し、脚注を本文の後に保持 |
| 日本語とページ引用 | 総ページ数のみ | 実ガード通過後も日本語・絵文字とUTF-16位置が一致し、該当ページを返す |
| 画像・本文・白紙の混在 | 他ページの文字で全体が成功 | ページごとにextracted/unread/blank/partialを区別 |
| 101ページ・長文 | 上限超過で文書全体が失敗、または後段短縮 | 抽出済み本文と未取得範囲を保存 |
| 表・回転・文字化け | 検出なし | 未確認理由を記録し、数値や単位を保持 |
| 誤ったContent-Type | PDF判定なし | PDFシグネチャで認識し、不明なバイナリは拒否 |
| 本文の短縮・変換 | ページ対応なし | 残った区間だけ位置を付与し、変換不一致時は位置を出さない |
| 出力・画面 | 原典URLと本文位置 | PDFページ、ページリンク、未読範囲が表示される |

着手時の既存PDF・Crawlerテストは8件成功。追加の品質テストは生成した固定資料による回帰評価であり、実論文の品質ベンチマークやOCR精度評価の代替ではない。

対象検証は `bun --bun vitest run tests/pdf.test.ts tests/pdf-quality.test.ts tests/pdf-lifecycle.test.ts tests/crawler.test.ts tests/crawler-live.test.ts tests/web-ui.test.tsx`。全体検証は `bun run verify`。カバレッジ保存先が他の実行と競合する場合は、同じ全テストを `bun --bun vitest run --coverage --coverage.reportsDirectory=/tmp/deepstill-pdf-coverage` で実行し、型検査・lint・format・build・docs:checkも確認する。

## 検証結果

最終版の対象テストは31件成功。全体テストは235件成功し、カバレッジは行89.00%、分岐81.35%で既定の80%閾値を満たした。型検査、lint、format、Webビルド、仕様書lintも成功した。lintには既存の52警告が残る。標準のverifyは別Vitest実行との保存先競合で停止したため、全テストのカバレッジ保存先を分け、残りの検証工程は個別に確認した。
